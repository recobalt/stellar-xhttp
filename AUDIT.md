# Проверка и изменения Stellar

Исходный репозиторий: https://github.com/recobalt/XHTTP-Installer, коммит `486797f5ff6030f425fc65833bccebac44f0ff29`. Проверка: 17 октября 2026. Подготовлены локальные файлы; GitHub и пользовательский VPS не изменялись.

## Изменения

- Рабочее название Stellar: исходники, имена файлов, службы, пути, сокеты, переменные окружения, тесты, схемы, сообщения и встроенный архив. Старый растровый баннер заменён на SVG с названием Stellar.
- Загрузчик получает основной файл и SHA256SUMS из одного коммита `recobalt/XHTTP-Installer`.
- Основной файл теперь `stellar-xhttp-install.sh`; старый `nuvrion-xhttp-install.sh` отсутствует в этой поставке.
- По умолчанию отключены Traffic Control, блокировка входящего ping, тюнинг и обновление Ubuntu. Для включения добавлены `--with-traffic-control`, `--with-two-way-ping`, `--with-tuning`, `--with-updates`.
- Устранён SIGPIPE/141 при определении SSH-порта: awk дочитывает полный вывод sshd.
- Для новой ноды ключи REALITY генерируются через одноразовый контейнер `--network none` до старта ноды; повторной генерации после её старта нет. Существующий listener по-прежнему запрещает генерировать заменяющий ключ без исходного профиля.
- README содержит команду запуска, поля ввода, настройку панели, диагностику, ограничения переноса и список внешних обращений.
- Авторские уведомления исходного кода сохранены в LICENSE, UPSTREAM.md, THIRD_PARTY_NOTICES.md и copyright-комментариях. Исторические отчёты помечены как исторические.

## Проверка безопасности

Проверены загрузчик, исполняемый код основного установщика, Python helper, оба vendor-модуля, systemd-служба, сборщик, workflow, шаблон профиля и сетевые вызовы сайта. Встроенный архив проверен на состав и соответствие исходникам. Просмотрены тесты, документы и ссылки; это статическая проверка и локальные тесты, не динамический аудит VPS.

В просмотренном коде не обнаружены отправка SECRET_KEY/приватного ключа автору, майнер, добавление чужих SSH-ключей или скрытый удалённый shell. Это не доказательство отсутствия всех уязвимостей. Содержимое скачиваемых Docker-образов, пакетов Ubuntu и работающий сервер отдельно не исследовались.

Сетевые обращения остаются: GitHub, Ubuntu package repositories, Docker Hub/registry, ACME Let's Encrypt, DNS, api.ipify.org и ifconfig.me. Профиль использует DoH AdGuard/Comss. При явном включении Traffic Control появляются изменяемые блок-листы shadow-netlab/traffic-guard-lists и RDAP при просмотре IP. Эти списки не имеют независимой подписи; они влияют на доступность сервера. HTTPS и SHA256SUMS из того же репозитория не заменяют независимое доверие к издателю. Node работает с host networking и общим /dev/shm, поэтому контейнерная изоляция ограничена.

Непосредственная причина прошлого конфликта 443 не подтверждена: до отката не был получен владелец listener. Изменение порядка генерации устраняет сценарий, когда новую ноду запускают до генерации ключей. Остальные конфликты должны приводить к отказу, а не игнорироваться.

## Выполненные проверки

- Шесть тестов загрузчика: успешный запуск, интерактивный ввод, единый коммит, повреждённая сумма, ошибки загрузки/ревизии и неподдерживаемая ОС.
- Пять новых регрессионных тестов: большой вывод sshd без SIGPIPE, offline-генерация до старта, защита существующего listener и явное включение модулей.
- Сайт: 2641 проверка данных/разметки; проверки топографии; 61 проверка DOM-взаимодействий. Реальный layout и поведение браузерного dialog этим набором не проверяются.
- Bash syntax, Python compile, SHA256SUMS, git diff --check.
- Повторная сборка побайтно совпадает. В архиве 135 обычных файлов, опасных путей/ссылок нет; встроенный сайт побайтно совпадает с site/dist.
- npm ci --ignore-scripts: закреплённые зависимости установлены; npm сообщил 0 известных уязвимостей на момент проверки. Это не самостоятельная проверка безопасности зависимостей.

Полный Python/shell suite проверен на macOS с отдельно собранным Bash 5.3 и физическим временным каталогом /private/tmp: 199 тестов, 39 записей о сбоях, 6 пропущенных. Контрольный прогон неизменённого исходного коммита в той же среде: 194 теста, 40 записей о сбоях, 6 пропущенных. Новых имён упавших тестов относительно исходника нет; исправлен тест загрузчика, который не соответствовал README исходника. Сбои связаны, в частности, с отсутствием Linux /proc, Linux-команд и GNU stat на macOS; полный зелёный прогон на Ubuntu не заявляется.

Linux-only интеграции, ShellCheck и проверка изображений через Pillow здесь не выполнены (Docker daemon выключен, ShellCheck/Pillow отсутствуют). Требуется прогон GitHub Actions на Ubuntu 24.04, затем приёмка на VPS с ACME, reboot, firewall, rollback и авторизованными REALITY/XHTTP-клиентами. Не считать эту поставку проверенной эксплуатационной установкой до этих проверок.

## Обновление репозитория

Архив содержит полный новый набор файлов. Замените корневое содержимое репозитория набором из каталога Stellar-XHTTP-Installer, сохранив собственный .git. Удалите старые файлы с прежним префиксом, а не просто добавляйте новые рядом. Не удаляйте LICENSE и сторонние notices. Не загружайте серверные JSON с ключами, .env, node.env и backups в GitHub.

GitHub URL в README станет запускать Stellar только после публикации всего набора, включая install.sh, stellar-xhttp-install.sh, SHA256SUMS, tools, vendor, src и site. Если переименование выполняется через Git, просмотрите список изменений, закоммитьте и отправьте его обычным способом. Самостоятельной публикации из этой сессии не было.

Старая установка автоматически не мигрирует. Новый префикс меняет имена служб и файлов; используйте чистый VPS или отдельно спланированный перенос с сохранением профиля и ключей.
